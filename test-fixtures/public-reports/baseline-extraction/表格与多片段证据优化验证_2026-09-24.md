# 表格行与多片段证据优化验证

日期：2026-09-24。针对《开放式抽取质量基线》暴露的表格漏抽和单片段证据不足，在运行中的通用专业报告平台上做定向优化。公开 PDF 原件保存在 `test-fixtures/public-reports/`，没有修改；原基线快照也没有覆盖。本报告中的第 7 页与环评第 5 页参与了问题定位，因此结果是回归验证，**不能作为独立盲测准确率**。

## 本轮实现

1. 可读 PDF 的识别表格增加行级片段，`ref` 包含物理页码、表号和行号，保留边界框。清楚的数值单元格形成待审候选；缺值符号 `-` 只保留为行内容，不当作有效数值。模型收到行级片段，并被要求优先引用同时含字段名、值和单位的行。原有文字片段及已确认事实的来源位置保留。
2. 审核候选时可以改选“值所在位置”，再选最多两处同页补充证据。主位置必须直接支持所确认的值；跨页、重复或不存在的引用被后端拒绝。确认后事实来源和后续写作引用可同时回链这些片段。补充证据的语义是否一致仍由人核对。
3. 前端显示表格行标签、引用预览，并在主片段不含候选名称时提示改选或补充原文。候选依然不会自动进入事实台账。

页面实测：第 7 页的“地上建筑面积”模型候选原主片段只含 `15756.25`，界面正确提示名称不在当前片段；在“补充位置 1”选择 `p7-t1-r6` 后，可看到同时含“地上建筑面积 15756.25 ㎡”的行级摘录。此操作只检查了浏览器预览，没有提交该候选。后端集成测试另行验证了确认后的多片段回链及跨页拒绝。

## 自动化与边界

`cd backend && ../.venv/bin/pytest -q tests`：23 项通过。`cd frontend && npm run build`：通过。测试包含真实北京与江门 PDF 的行和值、`-` 缺值、带单位表头、重复抽取、已存在来源、同页补充证据、跨页拒绝和来源回链。应用前后端分别在 `127.0.0.1:8000` 与 `127.0.0.1:5173` 正常响应。

本轮没有对全部 40 个基线核对点重新做人工盲评，也没有证明开放式抽取达到可直接写作的准确率。表格识别依赖原件版式，跨页、无边框与合并单元格表仍需扩样；模型仍可能改写字段、混淆条件或重复命名。旧候选不会因出现更好行级证据而自动替换。下一次质量关口应使用未参与本轮调试的新报告页，记录固定人工标注，再测值、单位、字段语义、证据和审核工作量。
