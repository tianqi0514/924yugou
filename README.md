# 语构 · 通用专业报告平台

面向专业报告的本机写作工作台：项目文件 → 人工确认事实 → 规则计算 → 章节候选 → Plate 编辑 → 核对 → DOCX / PDF / 审计包。

当前版本可以运行和演示，是一个有明确边界的开发基线。它不等于已经具备跨行业自动完成整份专业报告的能力。

每个项目左侧固定显示“项目文件、项目资料、项目事实、规则计算、报告写作”，模型配置为全局入口。项目没有对应内容时显示空状态；澄岳的历史语料在“项目资料”中只读，项目文件、事实和规则没有配置时为空，不能直接修改历史资产。报告工作台允许从其他菜单返回当前报告，页面刷新及浏览器后退保留项目与当前页面。

## 最新可用流程：方案推演与报告工作台（2026-09-26）

当前本机真实数据库环境从统一的“报告写作”进入正文中心工作台；“历史文章整理/资料起草”是保留的旧受审流程入口。当前可操作的是**有明确假设和来源限制的情景分析**，不是对现实项目事实的正式结论。

1. 选澄岳精密项目 →“报告写作”→ 打开现有报告或新建报告。点“输入数据”，新建方案并明确选择“采用澄岳历史输入”；普通新项目选择“从项目事实创建”，若项目事实为空则方案也为空。
2. 修改需求、工作日、产线参数或供应商。可单独“保存方案”，也可预览推演后“保存方案并运行”创建不可变运行；取消预览不写数据库。未保存的输入草稿在本机当前浏览器会话内刷新后仍可恢复，也可点“放弃修改”。历史值仍标“历史参考”，修改项标“方案假设”，报价未知显示“待补”。
3. 在“推演结果”查看数值、公式及上游，选两套方案“加入比较”，选择一次运行为报告依据。已写正文不会自动被覆盖；旧运行引用进入“检查”的待更新列表。
4. 点击“生成本章”，选 S4 产能与交付、S7.1 设备购置与报价或 S5.2 配电资料分歧；候选先预览，确认后才进 Plate。S4 可调用“模型起草”，使用现有模型配置中的文本路由，模型不可达时使用“确定性内容”或手工写作。
5. Plate 正文可编辑、输入 `/` 调出菜单，工作稿自动保存，Cmd/Ctrl+S 可手动保存。修改方案后重新选择运行，在“检查”点“处理变化”：逐项预览并选择更新正文数字、结果表、已知条件句或供应商判断；取消不修改正文。人工改写的句子和表格若能准确定位旧值，可查看前后对照并明确勾选更新；无法安全定位时保持阻断并返回 Plate 核对。剩余旧引用继续阻断核对与导出。全部处理后人工核对，下载“情景分析报告”ZIP。正式事实结论导出会阻断历史假设。

当前验收示例：300000 套首年需求、300 天时合格能力/销售 254016 套、缺口 45984；复制方案改为 250 天并将供应商换为“新供应商甲”，合格能力/销售 211680 套、缺口 88320，报价仍待补。交付示例见本机 `deliverables/澄岳精密_情景分析报告_20260925.zip`，测试输入和证据边界见[本轮验收记录](docs/方案推演与写作工作台验收_2026-09-26.md)。生成文件不纳入 Git。

本轮新写作路径直接消费部分 CAT-09/12/13/15/18 记录；30 类资产仍全部入库可浏览，历史资料的逐类配置与移除实验在次级“资料起草”入口可用。**30 类可浏览不等于 30 类都支撑了当前成稿。** 可精确定位的数字和已配置条件句可逐处预览更新；位置有歧义时，用户先在 Plate 改正文并保存，再在“检查 → 处理变化”核对“绑定当前推演”或“解除旧引用”。重绑核对当前运行值、单位及已知条件；旧值未删除或仍有未处理引用时不能核对。任意语义改写、复杂拆分合并、章节排序、规则独立修订和持久任务恢复仍在[开发清单](docs/开发清单.md)中；见[人工引用重绑与解除验收](docs/人工引用重绑与解除验收_2026-09-26.md)。

## 技术组成

- 前端：React 19、TypeScript、Vite、Plate 53、React Flow。
- 后端：Python 3.12+、FastAPI、SQLAlchemy、Decimal受限规则、python-docx、ReportLab。
- 存储：PostgreSQL 16保存项目/语料/事实/报告；项目上传原件保存在服务端本地存储。
- 模型：可配置兼容文本对话、视觉、MinerU等接口；调用只产生待审核结果。
- 当前没有登录、多租户权限、向量库、独立图数据库或 Semantica 运行时。

Plate 已集成本流程需要的章节层级、正文、引用、列表、表格、链接、事实引用、斜杠菜单、撤销重做、粘贴、保存/比较/导出；没有复制 Plate 演示站全部插件。

## 从 GitHub 安装

### 1. 环境

需要 Git、Docker Desktop（或 Docker Engine + Compose）、Node.js 20.19+ / 22、Python 3.12+ 和 `uv`。当前验证环境为 macOS；Linux和Windows尚未完成整轮安装验证。首次安装和拉取PostgreSQL镜像需要网络，配置模型前可以走手工事实与确定性写作流程。

```bash
git clone https://github.com/tianqi0514/924yugou.git
cd 924yugou
docker compose up -d --wait
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r backend/requirements.lock
uv pip install --python .venv/bin/python --no-deps -e backend
npm --prefix frontend ci
```

`frontend/package-lock.json` 与 `backend/requirements.lock` 锁定交付依赖；更新依赖应单独测试。所有后续命令如无说明均在仓库根目录执行。

### 2. 初始化数据库与内置资料

```bash
PYTHONPATH=backend .venv/bin/python backend/scripts/bootstrap.py --with-public-reports
```

首次导入及公开长报告解析可能需要数分钟。此命令先创建项目表，再导入并核验澄岳语料，最后建立四份公开报告各自的演示项目。可重复运行，不清空既有事实和报告。仅需澄岳时省略 `--with-public-reports`。四个普通演示项目只有原件和定位片段，事实台账为空，不会自动批准候选。

首次启动后端后会登记澄岳语料项目，历史资产保持只读；项目自己的专题工作稿可新增与编辑。入库后正常浏览从 PostgreSQL 读取语料，源文件目录仅用于初始化、核验与重建。禁止执行历史包内的 `validate_package.py`。

### 3. 启动后端、前端

终端一，在仓库根目录：

```bash
cd backend
../.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

终端二，在仓库根目录：

```bash
npm --prefix frontend run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。健康接口：[http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health)；接口结构：[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。前端`/api`代理到后端8000。

数据库仅映射 `127.0.0.1:55432`，前后端默认也只监听本机。Compose中的 `report / local_development_only` 是公开的本机开发账户，不能作为团队部署凭据。

停止：前后端终端分别按Ctrl-C，再运行 `docker compose down`。常规停止不要加 `-v`，该选项会删除数据库卷。

## 第一次使用

### 查看30类历史资料

1. 项目下拉框选择“澄岳精密”，打开“项目资料”。
2. 按七组进入类别，查看业务记录、图谱和来源；“作用说明”按需打开。
3. #23可核对800/650 kW未解决冲突；#11显示“向量未生成”。这些是历史数据，不会被自动填入新项目。

### 在澄岳项目生成并保存文章

1. 选择“澄岳精密”→“报告写作”→“历史文章整理”，选产能与交付、配电资料分歧或设备购置与报价，填写标题。
2. 点“生成候选”，逐段看正文及切块 ID；“查看本次输入”可核对模型实际收到的原文。取消不会创建文章。
3. 点“确认并保存文章”。左侧出现已保存文章；点击 Plate 正文可打开来源，继续编辑后先“预览改动”再“确认保存”，刷新可见新版本。

这条路径使用模型配置中的“章节起草”文本模型，模型未配置或返回不合格内容时会明确报错。当前只取所选章节的入库 outline 与原文切块（CAT-04/09），没有把其余 28 类宣称为本次文章输入。模型生成内容始终是待人工核对的历史专题工作稿；不提供正式报告核对与导出入口。历史语料、项目事实和其他项目不会因生成文章被改写。

在普通项目的“报告写作”选择只读参考和章节后，可展开“资料应用”。七组中的每一类都有“作用”入口，并可将本章使用方式设为“自动选用 / 仅核对 / 不使用”。保存的是本项目本章节的配置，保存后写作包刷新，先前的条目审核与候选须重新完成。一次可勾选1–6类，选择“移除类别”或“等价信息”后模拟，比较原配置、当前设置与逐类移除的候选差异；可用本项目事实或仅用于模拟的示例值。模拟不会写入事实、规则或报告。当前仅 S4、S7.1、S5.2 支持候选对比，其余章节可查看作用和保存配置，但不据此判断写作贡献；“移除后受阻”首先表示当前实现有依赖，不证明该类信息不可替代。等价模式以同一历史信息的类型化QA契约重建全章，并对所选类别做错误信息探针；可展开查看字段、比较与探针结果。未适配的类别如实标为未适配，替代结果仅用于模拟，不作为新证据或直接入稿。

### 不依赖模型走一遍写作

1. 新建普通项目，上传 [合成QA原件](test-fixtures/ux-integration/项目事实_QA合成原件.docx)。它只验证软件，不是业务证据。
2. 在“项目事实”创建数值事实：`first_year_demand`需求300000套、`qualified_capacity`合格能力254016套、`planned_sales`计划销售量暂不填。逐个预览并确认两个输入，并绑定到上传原件的对应片段。
3. 在“规则计算”创建目标 `planned_sales`，表达式 `min(first_year_demand, qualified_capacity)`，得到254016套。
4. 在“报告写作”新建报告，选澄岳v2只读参考和S4章节。“映射事实”将N017/N034/N035分别映射到以上三个字段，核对必选记录和来源，预览候选。先取消一次，再重新生成并确认加入报告。
5. 在Plate输入 `/` 插入表格，使用“事实”插入引用；预览改动并保存，刷新检查。进入核对导出，处理阻断项，人工核对后下载ZIP。
6. 把需求预览为0：计算也为0，取消不改变300000。确认后旧引用过时，正式导出被阻断；回到该章节生成新候选，查看待替换旧段落，确认“替换本章”；其他章节和未归属段落保留，手工事实引用仍须更新。绑定当前修订对应的新证据并重新核对后才能交付，旧正文可在报告版本中核查。

ZIP含 `report.docx`、`report.pdf`、`audit.json`。关键冲突、缺证据或过时引用不会静默放行；允许的预审稿明确标示保留事项。点击正文事实可追溯项目事实、规则、输入与原文。澄岳的三个章节演示不应套用到事故/审计等不同类型报告。

### 使用模型抽取和起草

在“模型配置”新增真实可达的端点、model与API Key，测试连接并绑定“事实抽取”“章节起草”或“扫描页识别”。预设中的本机地址只是连接示例，不代表内置了模型服务。已保存的本机配置不会被模板替换。

上传PDF/DOCX后按页抽取，核对候选的主语、单位、值、时点与引用后确认入账；候选不等于项目事实。报告页的 S4/S7.1 模型起草需先选中适用记录，再点“起草依据”查看实际将发送的本项目事实修订、规则、受审结构/论断/写法及未发送项；确认查看后才能预览。输入快照的摘要与候选绑定，项目、报告或资料变化时旧输入不能静默复用。候选逐段显示实际引用，取消不会入稿；确认写入报告版本和模型输入审计。当前模型校验是两章限定规则，不能代替专业审核。模型未配置或不可用会显示状态，不用固定文字冒充模型输出。图片生成/向量模型可登记和测试，当前没有写作功能消费它们。

## 备份、升级与重建

升级既有实例前停止写入并备份数据库：

```bash
mkdir -p backups
docker compose exec -T postgres pg_dump -U report -d report_platform -Fc > backups/before-upgrade.dump
```

同时在安全位置备份 `storage/`；只备份数据库无法恢复上传原件和模型密钥。运行 `bootstrap.py` 可补齐当前新增表与语料数据；本项目尚无完整版本化迁移系统，升级前须核对[开发清单NEXT-10](docs/开发清单.md)。

冻结语料需要重新生成数据库投影时：

```bash
PYTHONPATH=backend .venv/bin/python backend/scripts/import_builtin_corpus.py --rebuild
PYTHONPATH=backend .venv/bin/python backend/scripts/verify_corpus_file_purposes.py
```

`--rebuild`先核验源复制件，再事务化重建语料投影；不是重新抽取报告，也不执行历史脚本。恢复数据库属于覆盖操作：停后端、确认备份时点并保留当前快照后，可使用 `pg_restore --clean --if-exists --no-owner --no-privileges` 恢复到指定库；此操作会失去备份之后的数据，不在启动命令中自动执行。

## 项目内推演与章节配置（NEXT-20）

从“报告写作 → 规则与章节配置”新建草稿，录入字段、受限规则及章节指标，保存后输入样例试算，再发布版本。发布版本只读；“新建版本”复制其结构供修订。进入报告的“输入数据 → 按已发布配置创建方案”，可建立空输入方案，录入并预览推演，保存运行后选择“用于报告”。“生成本章”按配置章节产生可取消的数值摘要和表格，确认后进入 Plate。新版本不会自动改动旧方案、运行或报告。

配置只在当前项目可见；空方案不继承澄岳历史数值。样例试算不写项目事实；0 与缺失严格区分。章节可配置必要原件证据字段、受限比较条件的两种文字及模型禁用表述；运行冻结条件结果。经核对的原件证据和条件同时具备时，可用已配置的文本模型起草该章候选，模型文字仍需人工核对。澄岳原有三章的受审写作路径仍单独保留。详细输入、失败条件与验证记录见[规则与章节配置验收](docs/规则与章节配置验收_2026-09-26.md)及[非可研样本验收](docs/非可研条件证据写作验收_2026-09-26.md)。

## 当前限制

- 30类全入库不等于30类均必要；三章、15组合的合成等价实验只证明承载形式可以替换。更多报告类型、真实新项目证据和人工金标仍缺。
- 澄岳模型受审写作包输入覆盖 S4/S7.1；非可研样本另验证两章的条件与证据配置。二者不能证明跨类型自动成稿。候选取消/拒用全过程审计、规则配置审批和不可变交付快照仍需补齐；完整语义Diff、正文反向修订事实尚未实现。
- 澄岳文章整理仅开放三个历史章节，数字校验主要检查逐段所引切块；来源名称、推理和专业判断仍需人审。历史文章没有通过正式报告的项目事实与原件闸门，故只保存工作稿。
- 证据绑定和数字闸门主要为位置/词面核查，不能独立判断真实性、因果或专业结论。历史内部附件大多不完整。
- PDF跨页表、复杂合并单元格、OCR字框回链与长任务恢复不足；多页抽取一次最多8页，每页最多12000字，关闭页面可能中止后续页。
- DOCX复杂原版式、PDF宽表、中文字体细节与专业报告目录页眉仍需扩展测试。
- 无认证/权限，不应直接暴露到团队网络；需完成迁移、备份恢复和部署安全清单后再做团队试点。
- 主前端包约1.45MB（gzip约449KB）有体积提示；已验证流程可用，按页面拆包列为后续性能项。

数据来源与使用边界见 [NOTICE](NOTICE.md)。

## 本轮数据库升级与恢复

迁移前备份位于本机 `backups/scenario-workbench-20260925/`：`report_platform.dump` 与 `storage.tar.gz`。已用 PostgreSQL 16 的 `pg_restore -l` 验证备份目录可读；尚未在独立实例完成恢复演练，不能把“备份可列出”写成恢复已验证。当前后端启动时执行兼容新增表/列操作，保留既有项目、报告、语料和版本；更新代码前应先备份运行库和 storage。
