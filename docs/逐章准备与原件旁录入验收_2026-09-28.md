# 逐章准备、原件旁录入与论断核对：预设验收

日期：2026-09-28。此节在实现前固定输入与失败条件。只在 `report_platform_test` 写 QA 数据；本轮不迁移日常库结构，不改历史语料。

| 用户动作 | 固定输入与预期 | 失败条件 |
| --- | --- | --- |
| 新建空白可研 | 政府投资与企业投资报告各有独立章纲；无已发布本项目配置的章显示「待配置」，不继承澄岳值 | 空白章显示「可起草」或历史事实 |
| 准备文字章 | 本章配置要求一个证据事实：不存在时指向「项目事实」，有值但未核对原文时指向「核对来源」；完成原件绑定后显示「可起草」 | 只因值非空就认定来源已核对；把原文位置核对标为独立真实性认证 |
| 准备计算章 | 所需证据齐备但没有匹配配置的有效运行时，指向「输入数据/推演」；缺值与有效 0 分开 | 沿用旧运行或把缺值当 0 |
| 当前章论断与冲突 | 记录的支持/反对来源可点击到原文；未解决问题显示在该章准备详情中，已有正文不能因问题隐藏而保持已核对 | 只显示问题数量、无定位入口；冲突单方消失；选择方案假设即视为冲突裁决 |
| 原件旁连续录入 | 测试 PDF/DOCX 两段含 `0` 和 `12` 的原文，加入两条事实；预览只返回值、单位、位置和匹配状态，取消数据库不变；确认一次事务写入两事实、修订及当前原文位置绑定 | 第二条失败但第一条已写入；0 当空；无来源值被标原文已核对；重复或过期提交写入两次 |
| 故障与归属 | 批次中一条不受原文支持、跨项目文件、项目版本变化分别拒绝；刷新后已保存事实可在台账及来源页打开 | 半提交、跨项目引用、旧预览覆盖新修订 |

测试依次执行：后端隔离库接口与事务测试 → 前端构建及定向交互 → 真实前后端浏览器点击、刷新和约 900px 宽度检查。北京可研作为现有真实文件入口核查；合成短原件仅用于可重复的事务边界测试，不作为专业内容质量证据。

## 实际交付与验证

- 在章节目录点击状态，可看到当前章需要补的事实、值、原文核对、运行或配置；已有正文也不会隐藏待办。未决论断在同一面板给出入口，点击后显示支持来源、独立核实状态，并可回到原文片段。
- 在项目文件的具体段落点“录入事实”，同一份原件最多放入 20 项。前端显示名称、类型、值、单位，按需展开字段 key、口径、时点；任一项变化使旧预览失效。切换页面/项目时未保存录入会先询问。服务端一次事务写入事实、修订、来源绑定及固定原件摘要/解析修订的证据；空值不伪造来源核对。

- 真实后端与前端、隔离测试库、真实浏览器全套集成回归 **15/15** 通过，含北京可研、江门环评、Plate 编辑、报告刷新、版本与交付。新增章节流程单测从“缺资料”点进预填表单，再在 DOCX 原文旁加入两项，预览/取消数据库仍为空，确认后来源回链、论断跳转和 900px 无水平溢出；增加未保存离页拦截后该用例 **1/1** 再通过。最终前端生产构建通过。本轮未重新调用真实模型，也未重新导出并逐页目视核查文件；既有集成用例仍检查 DOCX/PDF/审计内容。

## 判定与剩余边界

上述验证证明“看章节缺项 → 回原件补事实 → 回章节查看就绪与论断来源”这条软件操作可用。原文片段含数字只说明位置和值的字面匹配，不能证明单位、口径、预测真实性或专业论断已经独立核实。批量录入目前只在同一原件下进行；多原件合并审核、复杂表格语义和专业金标仍需后续验证。内置澄岳 30 类继续作为只读历史资产，本轮没有把其数值复制到新项目，也没有新增 30 类必要性的跨项目结论。
