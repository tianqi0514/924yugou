# 30 类语料如何支撑写作：演示脚本

打开 `http://127.0.0.1:5173/`，选择 **QA-写作支撑验证 · 2026-09-24**。这是合成 QA 项目，不是澄岳精密历史项目；本轮已准备好三节预审试验稿。

1. **看事实与规则**：在“项目事实”看首年客户需求 `300000` 套、合格能力 `254016` 套；在“规则计算”看本项目 `min(first_year_demand, qualified_capacity)`，结果为计划销售量 `254016` 套。事实来源明确写着“QA 合成输入”，没有冒充已核对原件。
2. **看参考怎么选**：进入“报告写作”，打开 **QA 需求、能力与设备报价试验稿**。只读参考是 `cy_tray_20260918@v2`。选择 S4 时，写作包逐项标出必选的章节结构、模板、C0052 骨架、R006 模式和 L002 论断；点“查看来源”可追到入库记录。EV-01→EX-01-01 能看到第 17 页摘录及完整原件缺失说明。
3. **看成稿和 Plate**：报告 v5 已有 S4、S5.2、S7.1 三节。S4 的 `254,016` 来自本项目计算；“需求不是订单”只作为保守提醒。S5.2 只披露历史 X001 冲突并留“待核实”表格；不会得出配电适配结论。S7.1 写新供应商“新拓设备”及本项目 QA 单价，不含历史供应商或报价范围。点击事实 token 或历史来源按钮，可反查依据；输入 `/` 可插入标题、列表、引用块、表格与链接。
4. **看证据闸门**：在“核对与交付”看阻断项。需求、能力、供应商、报价没有绑定本项目完整原件，X001 也未解决，所以**正式导出受阻**。只能点击“导出预审稿”，ZIP 中的 DOCX、PDF 和审计 JSON 都标明预审状态。已解包复核的文件在 `demo-output/`。
5. **看 30 类结论**：打开 `docs/写作支撑验证报告.md` 的逐类矩阵。报告区分写进段落来源、只用于核对、未被消费和向量尚未生成；遮蔽只造成固定代码报错的类别没有被夸大为写作必需。

如要演示事实变更闸门，切换到 **QA-事实变更引用闸门 · 2026-09-24**：`test_qty` 从 `10` 改为 `12` 后，旧报告第 3 段先被标为待更新；即使正文已显示 `12`，也必须点“预览引用核对”并确认保存，事实绑定才更新到 r2。项目文件里的《事实修订合成原件.docx》明确标着“仅供软件测试”，其第 3 段已与当前事实绑定；之后可人工核对并导出一份 **QA 正式闸门测试包**。这只验证软件的修订、原文定位和导出控制，不能证明合成材料代表真实业务事实。
