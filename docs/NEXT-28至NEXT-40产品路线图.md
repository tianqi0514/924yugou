# NEXT-28 至 NEXT-40：可研写作产品路线图

编写：2026-09-27。基线：`b549a14`。**以下 13 项全部为待开发或待验证计划，不代表当前能力；本轮只更新规划文档。**

## 1. 这一阶段要交付什么

让用户用自己的项目资料完成一份可继续修改、逐项核对、按明确用途交付的多章节报告：选择报告类型与章纲 → 准备本章依据 → 修改方案并计算 → 起草文字论证与计算章节 → 在 Plate 编辑 → 处理事实、证据和正文变化 → 核对并交付。

评价分为两个独立结论：软件流程是否可靠；专业内容是否得到合格审核者认可。前者可以由开发和回归测试验证，后者需要专业人工评审。没有评审记录时，专业质量保持“待验证”。

本阶段以可研为主要验证领域，仍采用本机/私有化单用户部署。报告类型和章节要求进入版本化配置；政府投资、企业投资以及项目建议书/代可研的适用范围分别记录。2023 年国家发改委文件分别给出了政府投资与企业投资的大纲，并允许结合具体项目及行业特点调整。这里只以其为章纲设计参考，实际项目采用的版本、行业规定和适用性须单独核对。[国家发改委原文](https://zfxxgk.ndrc.gov.cn/web/iteminfo.jsp?id=20220)

### 现状核查带来的决定

| 当前事实 | 对规划的影响 |
| --- | --- |
| 北京样本已验证面积、用地、投资三章分项复算，原件是项目建议书（代可研） | 能复用计算和编辑闭环；不能将这三章当成整份专业可研的质量证明 |
| `analysis_config._normalize` 要求章节至少选择一个数值指标；`draft_preview` 必须绑定运行 | 文字论证章必须允许没有计算指标、没有 `run_id`；不能伪造一个计算运行过接口 |
| `_configured_model` 主要接收运行值、预设条件句及来源核对状态 | 需要有明确引用范围的原文证据与论断输入，才能验证文字论证；仅增加提示词不够 |
| `section_evidence` 与 `FactEvidenceBinding` 主要围绕事实值及原件位置 | 要补文字证据、多来源、证据修订及“支持到什么程度”；原文位置存在不等于论断成立 |
| 30 类配置主要位于旧资料起草，主工作台只使用部分记录；普通项目资料聚合文件与事实 | 要将相关资料、策略与实际用途接入同一章的写作包，逐步收敛旧入口 |
| Plate 已具备基本格式、候选采用、保存、版本、局部变更、导出 | 下一步验证拆分/合并/复制/表格编辑的引用保真，以及改稿后的局部核对 |
| 方案创建、不可变运行、最多三次运行比较已存在 | 后续只补可比性检查、敏感性批量计算与决策依据，不重复做基础方案比较 |
| `init_db` 仍含启动时增量 DDL；写作任务未形成重启可恢复队列 | 新表实施前先建立迁移基线；后台任务和发布恢复分别完成，不把成功同步请求当成可靠任务 |

## 3. 逐项范围与可证伪验收

### NEXT-28：专业文字章的最小闭环与评价基线

**用户动作**：在现有工作台选择“建设背景/建设必要性”中的一个有依据的小节，选取原文依据，生成候选，逐段核对或拒用，确认后进入 Plate。用户不必为了写文字章先填数值、建方案或运行计算。

实施范围：

- 在既有配置和起草服务上支持文字、计算、混合三类章节；类型控制输入需求。计算引用仍要求有效运行，文字证据允许独立绑定。界面保持“生成本章”，无效的计算操作按章禁用。
- 先做少量经选择的项目原文片段，冻结文档身份、修订、位置、摘录及使用范围。模型返回正文与实际引用的证据项；来源不足时保留缺口或限定为对原报告的转述。
- 实现该章最小的证据→候选→人工采用→段落回链。沿用同一工作台、报告版本和来源约束，不新建专用演示页。后续 NEXT-29 再扩展证据管理范围。
- 开发前固定评价集：覆盖直接支持、部分支持、没有依据、互相矛盾、拟实施/已实施、历史/当前、主体错配、缺原始附件八种情形，每种至少两个明确判例。为第二份独立可研预留未参与提示词调试的章节。
- 开发者整理的标签只能称“开发参考标注”；至少一位具备相关业务经验的人工审核者确认后，才能将对应条目称“专业金标”。记录异议和未核定项，不让生成模型自评后直接标通过。

验收：不带 `run_id` 的文字章可取消、采用、刷新并回链，至少一次使用现有配置中的真实内网文本模型完成该流程；模型不可达则登记未通过并继续独立功能，不用替身冒充。“拟申请资金”不得作为已落实资金放行；旧报告的必要性表述不能自动升级为新项目判断；删除关键依据后相关论断不能继续保持已核对。记录模型原始候选错误、拦截结果和人工修改后质量，三者分别计数。所有高风险无依据判断必须在入已核对稿之前被拦下或被人工删除。

完成物：一章用户可操作的待核对文字稿、一组版本冻结的开发参考判例和一份专业审核待办/审核记录。若原件不足以支持必要性结论，就交付有来源的背景转述与明确缺口，不补造结论。

### NEXT-29：项目证据库、多来源与原件版本

**用户动作**：在“项目资料”选中原文或表格，登记为本项目证据；在章内选择要用的证据、查看支持内容及限制；上传新版原件时查看会影响哪些事实和章节。

实施范围：

- 扩展现有事实原件绑定，支持独立文字证据和一项事实的多份来源。记录证据 ID、原件/解析修订、页段或表格位置、摘要、时间、主体和可得性；模型摘要与原文分开保存。
- 区分“原件位置核对”“来源陈述”“独立核实”“不适用/撤回”，不得用单一绿色状态代表全部可信度。
- 原件和解析结果用不可变修订保存。只识别内容摘要相同的重复上传；不同版本不自动合并。历史引用继续打开原位置。
- 新旧证据替换形成影响预览，确认才建立新绑定；互相矛盾的来源先并存，交给 NEXT-32 的问题处理。

验收：同一事实由两份资料支持；其中一份缺附件仍可见；上传新版后旧报告能打开旧片段，新候选使用新版需明确确认；跨项目证据 ID 被拒绝；仅有二手转述时不能冒称完整原件已核实。

### NEXT-30：报告类型、章纲与章节要求配置

**用户动作**：新建报告时选类型及用途，得到可修改的章纲；点击一章即可知道现有资料能否起草，并直接补充所需依据。普通使用者无需先理解字段 key 或规则表达式。

实施范围：

- 在现有 `AnalysisConfig` 版本和发布机制上扩展章纲、章节类型、证据要求、论证问题、允许的判断、表格及输出要求。业务配置编辑与普通写作入口分开。
- 为政府投资、企业投资建立不同的初始配置；记录大纲版本、适用范围和报告阶段。用户可删改章节，排除某项需记录理由；不适用不等于通过。
- 章节状态由实际输入得出：可起草、缺资料、待核对、不适用。工作台默认只显示短状态，详情点击展开。
- 从已发布配置创建新报告只复制结构/规则定义；事实、供应商、证据及旧审核结论不随模板复制。旧报告固定原配置版本。

验收：一个文字章没有数值也可写；一个混合章缺必要计算时仍明确显示阻断范围；空项目不带历史值；政府与企业项目使用各自章纲；配置升级不改变旧运行或旧报告。

### NEXT-31：统一写作包与 30 类资料实际应用

**用户动作**：在当前章的“资料”面板中选择参与起草、仅供核对、不使用；点击“作用”看到具体用于哪条依据、哪段候选或哪个核对动作。

实施范围：

- 将旧资料应用、显式语料版本引用和主工作台的章节上下文收敛到同一服务，继续沿用现有数据库身份。旧报告/地址保持可访问；接口失败应报错，不能通过自动切换旧工作台掩盖故障。
- 生成前固定写作包：项目、报告版本、章节配置、证据修订、事实修订、可选运行、语料记录、策略与摘要。候选采用时重新核对摘要和版本；输入变化使候选过期。
- 30 类策略可按章配置；未生成/不适用的类别有真实空状态。来源身份、归属及关键问题闸门是固定约束，不能因用户关闭某类材料而绕过。
- 分别记录“纳入候选包”“实际发送给模型”“候选引用”“最终段落采用”“用于核对”；不把模型自报引用当作已证明的写作增益。
- 普通项目按业务对象产生有用的资料记录和投影，保留历史 30 类资产。无需制造 30 份空文件或将所有材料放进模型。

验收：30 类都能解释当前章的实际状态；未采用项给出具体原因；在三类任务中比较最小包、适用条件类包、全部可用类包，并做受控移除/等价替换。正文、引用、人工修改量均记录，某类无增益时如实记为未证明。切换项目、报告或语料版本后，旧响应不能污染当前章。

### NEXT-32：论断、冲突与缺口进入写作流程

**用户动作**：在本章“检查”里处理一个判断：查看支持与反对来源，限定表述、补证、保留问题或拒用；处理后回到正文对应位置。

实施范围：

- 建立项目内可修订的论断记录：文本、主体、时间、条件、性质（来源转述/计算判断/假设/待审判断）、支持/反对证据、所涉章节和人工决定。
- 冲突保留双方记录及修订；选择某一分支做情景分析只建立假设，不自动裁决冲突。缺口记录所缺信息、影响的判断与处理状态。
- 问题按适用范围影响候选与交付：有未解决问题可以保留如实披露，不能同时放行相冲突的确定性判断。隐藏材料不能隐藏问题。
- 已有澄岳 L002、X001 及缺口记录通过适配复用身份，普通项目使用自己的记录。

验收：800/650 kW 冲突双方持续可查；预算意向不转为资金到位；预测需求不转为订单；缺原始批复不能写已批复；删除或过期的证据让相关核对状态失效。作用范围以实际引用与已登记关系为准，不宣称自动理解所有自由文字。

### NEXT-33：候选审阅、选区改写与采用

**用户动作**：选中一段，选择精简、重组或根据新依据重写，看到局部前后对照，接受其中一段或拒用，其余文章保持。

实施范围：

- 复用逐块采用，补齐候选逐段的问题与依据入口、人工改写后的再核对、拒用和取消事件。审阅不等于对业务真实性自动认证。
- 选区改写只发送选区、必要前后文及已允许证据；保留事实和计算绑定，禁止扩展到未经选中的章节。
- 候选持久保存独立身份与状态，为 NEXT-37 的后台任务复用；正文事务只在采用时发生。相同候选重复提交不重复插入。
- 冻结本次模型、调用参数/提示词版本、输入摘要及引用范围；密钥留在既有配置服务中。关键数字做字段与口径核对，不能只比较数字集合。

验收：候选生成时继续改正文，旧候选不能覆盖新编辑；取消、模型失败和拒用不修改报告；模型把数字放到错误主语下要进入待审/拒收；保留用户已改的段落和表格格式，采用后来源仍能回链。模型不可用时手工编辑和确定性计算内容仍可用。

### NEXT-34：Plate 复杂编辑与引用保真

**用户动作**：像使用普通文字编辑器一样拆段、合段、复制、粘贴、改表格；点击引用仍能打开准确依据。

实施范围：

- 将块级来源逐步细化为稳定的语句/引用范围和表格单元格身份；沿用现有事实和运行引用，避免一项引用变更让整篇失效。
- 规定拆分、合并、删除、撤销、跨章移动、粘贴和表格行列操作的引用迁移规则。歧义时明确标为待核对，不猜测绑定。
- 同项目复制产生新的出现位置；跨项目粘贴不得保留可冒用的项目引用，须提示重新绑定或保留未核对纯文本。
- 新属性同时覆盖编辑、校验、持久化、版本差异、来源定位和 DOCX/PDF；未知节点显式处理，不能静默丢弃。

验收：固定编辑矩阵至少覆盖拆分/合并、撤销重做、跨章移动、同/跨项目粘贴、表格增删行、结果单元格改写、保存刷新和导出；无引用丢失或错项目绑定。中文输入法组合中不重置光标，900px 与常用桌面宽度可操作。

### NEXT-35：全文一致性与双向修订提案

**用户动作**：修改一个事实或论断后，在“检查”看到受影响段落和局部对照；或在正文改数字后，明确选择仅改表述、更新方案假设、提出项目事实修改。

实施范围：

- 数据到正文：补齐跨章主体、单位、时点、总分项、条件及重复指标一致性。数值、表格、判断分别成为可接受/拒用的更新项。
- 正文到数据：仅对有稳定绑定和明确可解析的修改生成结构化提案；原事实仍需既有预览、确认、来源核对和事务。自由文字由模型提出的候选关联始终待人工核对。
- 每个提案固定报告、事实、规则、证据和运行水位；双方同时变更时返回冲突，不能覆盖任一方。拒绝提案不等于旧引用恢复有效。
- 按输入修订和已登记依赖定位影响；撤销正文修改不能暗中撤销已经确认的事实事务。

验收：正文 300000 改成 200000 时不会直接改事实；“拟批复”改为“已批复”必须核对新证据；同一金额出现十处，只更新用户确认范围，剩余位置保持待处理；并发修订和重试无半提交。未登记的自由文字语义范围明确标为未自动检查。

### NEXT-36：敏感性推演与方案采用理由

**用户动作**：选择一个输入和几个试算值，查看哪个值会改变关键结果/判断；把两至三套可比方案写成对照表，并记录采用理由和限制。

实施范围：

- 复用方案复制、Decimal、运行与比较；新增可比性校验（指标身份、单位、时点、范围及配置版本）。不一致项逐项说明，不能直接算差异率。
- 首版支持单因素、用户显式给定的有限值列表；先给计算规模，限定批次大小。结果都保留输入、规则与不可变运行，不引入随机预测或自动求“最优”。
- 0 基数的变化率显示不适用；缺值不参与伪比较；所有假设在表格和段落中标明。关键冲突分支保留未裁决身份。
- 对比段落明确每列/每个结果对应的方案与运行；其他正文仍绑定主运行。采用理由是可审查的决定记录，与 CAT-21 的历史实例只建立显式参考。

验收：工作日 300/250 的固定产能用例和北京工程费变化产生正确结果；0、缺失、不同单位/年度和阈值相等分支都覆盖；采用一案不改另一案或旧报告；来源之外的专业评价不会由数值排序自动生成。

### NEXT-37：持久任务、取消和恢复

**用户动作**：生成或导出期间可以离开页面，回来看到准确进度；失败可重试，取消后不会迟到入稿。

实施范围：

- 使用现有 Python/PostgreSQL 加本机工作进程，保存任务、尝试次数、输入摘要、幂等键、进度阶段、结果位置、取消请求和失败原因；无需为此引入大型调度系统。
- 任务冻结写作包。长模型请求期间不持有报告写锁；结果提交检查任务归属、取消状态与输入水位。服务重启时识别失去工作进程的任务。
- 对调用结果不确定的模型请求显示“不确定/需重试”；没有供应商幂等支持时不能保证模型只调用一次，但必须保证正文采用至多一次。过期 worker 的迟到结果不得覆盖新的尝试。
- 导出结果只有写入完整文件、摘要及成功记录后才显示可下载；生成任务完成仅产生候选，不能自动采用。

验收：模型超时、断网、重启、取消与完成竞态、重复点击、报告改版、跨项目回包均有确定结果；无重复入稿/交付记录，无假成功。用户界面仅保留任务短状态与继续/重试/取消操作。

### NEXT-38：多章节组稿、摘要与专业交付

**用户动作**：勾选已准备好的章节批量起草，逐章审阅；从已核对正文生成摘要，统一目录和版式，查看交付问题后导出。

实施范围：

- 组稿按章节依赖和固定写作包创建任务。各章独立候选，局部失败可重试，成功不覆盖其他章。缺资料章保留待办，不填空洞文字充完整。
- 摘要/结论只使用已核对章节的事实、运行和论断；摘要不能提出正文未支持的新判断。来源章改变后摘要失效。
- 支持目标可研需要的封面字段、目录、页码、标题/表编号、交叉引用、页眉页脚、引用清单、跨页表头和宽表处理。业务字段空缺直接提示填写，不生成虚构单位和日期。
- 预审稿、情景分析和正式事实结论沿用独立闸门；固定同一版本的正文、表格、证据、规则、运行和审计。版式升级生成新交付，不改旧文件。

验收：至少一份真实多章长文与一份覆盖跨页/宽表的合成排版夹具，逐页检查中文、目录页码、标题、表头和引用；DOCX/PDF/审计数值一致。材料不足时不强行达到章数；摘要不能写超出已审正文的项目可行结论。长文导出失败可恢复且不出现空下载。

### NEXT-39：独立可研验证、资料贡献与可用性

**用户动作**：一位未参与开发的操作者用另一份可研，从新项目走到交付，记录卡点；专业审核者评价实际章节。

实施范围：

- 使用 NEXT-28 预留的独立公开可研，优先与开发样本不同项目/编制来源；完整可研与代可研分别标注，不能把同一文件拆章充独立样本。模板、提示词和评分项在验证前固定。
- 覆盖文字论证、定量计算、冲突/缺口三类任务；模型配置和采样条件固定，至少重复三次记录波动。失败后修复属于新一轮，不抹去初次结果。
- 为 01–30 每类保留一行实际消费与增益结论，比较等价信息和缺信息，而非仅删文件；成本包括模型上下文、等待时间、人工改动和维护负担。统计未消费/无证据/实现依赖/实际增益。
- 检查首屏、章切换、原件搜索、编辑输入和导出。先记录设备、数据量、冷/热加载及分位值，在优化前冻结性能预算；针对超过预算的环节做懒加载、查询索引、分页或缓存。当前约 1.49 MB 主包是测量线索，不能单靠压缩体积证明体验好坏。
- 所有项目五项导航一致；空白/加载/失败可处理；默认一个上下文面板；Esc、焦点、返回、刷新、窄屏均走查。开发说明和审计细节按需展示。

验收：冻结案例中的严重无来源论断、跨项目串值、过时引用放行和交付不一致为零容忍；同时报告初稿支持率、论点覆盖、来源定位率、人工修改量、任务完成率与时间，给出分母和失败样例。软件验证通过、专业质量待核定时分别报告；不能据单一审核者或两个样本宣称跨行业成熟。

### NEXT-40：发行、升级与恢复

**用户动作**：按 README 安装或升级后打开原项目，模型配置可用、旧原件可查、历史报告及导出不丢失；故障时能按说明恢复。

实施范围：

- 统一启动、健康检查、依赖锁定、版本记录和兼容说明；发行范围仍为本机/私有化单用户。保持默认监听本机，团队网络准入另执行既有 NEXT-12。
- 基于每轮已完成的版本化迁移，做空库安装、从 `b549a14` 数据模型及本阶段实际中间版本升级、失败回滚或备份恢复；有破坏风险的降级明确使用恢复流程，不假定每条 DDL 可逆。
- 备份并恢复数据库、原件、交付文件与解密所需的配置密钥；密码/密钥通过本机安全方式保存，不进入仓库和验收包。遗漏解密密钥时必须报配置不可恢复，不能只看数据库计数宣称成功。
- 在隔离实例恢复后核对项目数、资产摘要、引用、运行、历史版本及可用交付；日常库不用于破坏性演练。设置可配置的存储用量提示与清理预览，保留引用中的资产。
- 发布说明链接完成证据、未完成项、专业审核范围和恢复步骤；文档与实际版本一致。

验收：干净环境可安装；旧项目成功升级；在独立实例从完整备份恢复并实际打开报告/下载旧交付；失败升级不会让日常数据半迁移。只有软件门禁通过才发布相应功能，专业评审未完成时仍标明局部写作基线。

## 5. 技术边界与实施门禁

新增对象只服务以上用户动作，优先扩展现有事实、原件、配置、运行、报告和事件模型。至少有可区分的证据修订、章节写作包快照、论断决定、候选、更新提案、任务和交付水位；不要让这些对象共用一个可任意改写的 JSON 状态，也不要照 30 类各建一套孤立表。

- 写作包中的 `run_id` 对文字章可空，对计算引用必需；包必须指向精确证据/事实/配置修订。章节模式不能用来绕过计算或来源检查。
- 每个采用、事实修改、方案保存、运行生成、核对和交付都各有事务与版本检查；预览不改业务对象，取消审计只记取消。
- 文档/证据、运行、写作包、报告版本和成功交付是不可变快照；工作稿、配置草稿和方案输入可以产生新修订。
- 第一项需要新表的实现前建立迁移版本基线并备份；每次迁移都测升级和失败恢复。NEXT-40 再做完整发行演练。
- 数据归属、来源完整性、密钥脱敏和过时引用阻断属于硬约束；章节写法、适用规则、材料策略、精度展示和输出版式可版本化配置。
- LLM 负责受约束起草和待审建议；Decimal 负责计算；有歧义的事实/论断/专业结论由人工决定。联网公开报告只作为明确选入的样本，来源文本不作为执行指令。
- 默认界面继续五项项目菜单和全局模型配置。每项新增动作放在对应页面/当前章节，主页面不展示技术 ID、原始 JSON 或整页操作说明。

## 7. 阶段退出条件与仍需的人工作业

第一批退出：一章有原文依据的文字稿，加上已有计算章，在同一工作台可写、可审、可追溯；30 类作用能按真实消费显示。若文字论证仍只能复述预设句子，应继续修复 28–31，暂缓扩章。

第二批退出：人工改写、原文改版、事实变更、条件变化后能准确指出受影响位置；确定性错误和歧义均不会被静默放行。复杂引用不稳定时，先完成 34–35，暂缓全篇批量起草。

第三批退出：明确可比的方案能推演并入稿；长任务可查询和恢复；多章文档与依据、审计一致。专业判断缺证处仍保留缺口。

第四批退出：新操作者用独立可研完成任务，软件问题修复并回归，发行/恢复演练完成。专业人工评审若仍缺失，发行说明保留“专业质量待验证”，不更改为自动完成可研。

专业人工需要提供/确认：报告用途及适用章纲、评价集中的判断范围、至少两类章节的合格示例与错误级别、留出样本的审核结论。开发可继续完成独立的证据、版本、编辑和恢复功能；不能把开发参考标注自动视为这些确认。

本轮文档验证范围：13 个 ID 连续且唯一、依赖无环、30 类映射覆盖完整、内部链接存在、各引用状态与已实现基线不混淆。本轮不运行应用回归，因为没有应用代码、数据库或业务数据变更。
