## 边界

PDF 解析依赖文字层与 PyMuPDF 的表格检测；DOCX 目前只处理表头明确的矩阵与简单数字键值行。扫描件、跨页及复杂合并单元格尚未验证为可用。表格行中的“单位”若原件口径含糊，系统不会替用户裁定；总额与分项、比例与金额的关系也未自动建立。人工确认仅表示选择了原文位置，原报告真实性和专业结论仍待独立审查。历史 30 类中的 CAT-08 保持只读资产，这次验证的是新项目表格进入写作来源的流程，不证明 CAT-08 在跨项目写作中的净增益。

## UX-29C 预注册：表格事实到交付

输入固定为测试库中的合成 DOCX 表格“首年需求 300000 套”“合格能力 254016 套”和未提供报价；另创建空的“计划销售量”结果，规则为两条已审表格事实的 `min(首年需求, 合格能力)`，内部 key 由候选确认时生成。先由操作者确认两条表格候选，再配置政府可研“需求分析与建设规模”章节，推演并写入报告。预期运行和正文中的计划销售量为 **254016 套**，原文回链分别指向 `d-t1-r2`、`d-t1-r3`；未提供报价不得成为数值事实，不能写作零元。取消候选不改报告，采用后刷新保留正文；情景分析导出的 DOCX、PDF、审计必须使用同一运行并包含 254016 与来源。失败条件为任何一处失去位置/版本、数值变成 0 或 300000、取消后入稿、导出闸门被误放行。此案例是合成软件验收，不是专业可研真实性证明。

### UX-29C 实测结果

`table-writing.spec.ts` 使用独立测试库和真实 8001/5175 前后端。界面确认两条候选后，事实值分别为 300000/254016，来源为 `d-t1-r2`/`d-t1-r3`；缺报价没有数值事实。配置本章后 `min` 预览和保存运行均为 **254016 套**。章节候选第一次取消后报告没有推演引用；再次生成并采用后，Plate 正文和刷新后的报告均保留 254016 与同一 `run_id`。用户在界面核对后，情景分析 ZIP 的 DOCX、PDF 含结果表及“推演依据”；审计中的两条 `run_input_sources` 各自固定事实修订 r1、原件 SHA、解析修订 ID、证据 ID、表格行 ref。解包脚本核实 DOCX/PDF 都有对应原件名与可读行位置，审计交付级别为 `scenario_assumptions_reviewed`。

本轮先暴露两处问题：章节预览把生成的内部 key 给用户看，导出只有运行数值而缺表格行。两处已修复并再次实跑。真实前后端 `chapter-mapping.spec.ts` 与新增的 `table-writing.spec.ts` **2/2** 通过；后端 `test_chapter_mapping.py`、`test_analysis_workflow.py`、`test_export_layout.py` **32/32** 通过；前端生产构建通过。测试生成的项目和交付只在隔离 `report_platform_test`/`tmp/integration`，没有用于日常项目；本轮无数据库迁移。

仍未验证复杂合并/跨页表、总分项和单位口径的专业判断；原件位置由操作员核对，独立真实性未验证。该合成数值章证明表格事实可以支撑一条有来源的情景分析计算，不代表真实可研全篇已能可靠生成，也不证明澄岳历史 CAT-08 对新项目的独立增益。

## UX-29D 预注册：真实可研 PDF 表格到章节交付

固定输入为仓库内北京交通枢纽可研 PDF 第 177 页、表 1 第 1 行的“工程费 22122.45 万元”（`p177-t1-r1`）。在独立测试项目中由用户确认这一候选，映射至政府可研“投资估算与资金筹措”，以原文数值作为本章指标，不新增计算规则或总投资结论。预期方案运行及章节候选保留 **22122.45 万元**；取消候选不写正文，采用后 Plate 保存刷新不变；DOCX/PDF/审计保留同一运行、原件 SHA、解析修订、证据 ID、页/表/行。缺失其他投资分项时，不得称投资总额已复核或资金已落实。此案例检验公开 PDF 的软件链路，不证明原报告真实性和项目投资合理性。

### UX-29D 实测结果

首次真实浏览器测试发现，纯原文指标没有规则时，方案预览和结果列表被“仅显示计算字段”的前端筛选清空；页面却写“已完成计算”。预览接口当时也未返回已发布配置的 `result_keys`。修复后，预览与保存运行共用配置快照装配，所选工程费在预览和运行结果中可见；方案对比已复用同一指标筛选，但本案例未操作双方案比较。无规则状态改为“本次无计算规则”。第二次测试在候选、Plate、DOCX/PDF 中发现“本方案采用”的用语不准确，现仅当所有指标来自项目原文时改为“所选原文列示 / 原文数值”。

真实浏览器完整操作了第 177 页识别、单元格查看、候选核对确认、投资章映射、方案预览与运行、候选取消与再采用、Plate 刷新、核对、情景分析导出和 900px 窄屏检查。事实及运行值均为 **22122.45 万元**；审计中 `run_input_sources` 固定事实修订、原件 SHA、解析修订、证据 ID 和 `p177-t1-r1`。解包校验 DOCX/PDF 都含原件名及“第 177 页，表 1，行 1”，没有“资金已落实”“总投资已复核”。PDF 单页渲染目视检查了标题、正文、表格、来源与页码；修复了来源分隔点显示方框的问题。真实前后端 `table-writing.spec.ts` 的 Word 与北京 PDF 两条路径 **2/2**，后端配置/导出/章节映射目标回归 **14/14**，前端生产构建通过。测试仅使用独立 `report_platform_test` 和临时原件存储；本轮无数据库迁移。

剩余边界：一条工程费引用不能推出投资总额、资金落实或专业合理性。跨页/合并表格、分项关系、来源真伪、专业人工审核以及历史 CAT-08 对新项目的净增益仍未由本案例证明。

## UX-29E 预注册：同一张真实投资表的分项复算

固定输入为北京交通枢纽可研 PDF 第 177 页“项目总投资汇总表”的五行：工程费 `22122.45` 万元（`p177-t1-r1`）、工程建设其他费 `2701.55` 万元（`p177-t1-r9`）、预备费 `1241.20` 万元（`p177-t1-r10`）、征地拆迁费 `5190.37` 万元（`p177-t1-r11`）、原文总投资 `31255.57` 万元（`p177-t1-r12`）。在全新项目逐行核对入台账，由用户明确建立四项求和与“原文总投资－分项合计”两条受限规则，映射“投资估算与资金筹措”章。预期分项合计 `31255.57` 万元、差额为有效 `0` 万元。章节候选、Plate 保存刷新、情景分析 DOCX/PDF/审计应保留五条行级来源及规则结果。方案副本把工程费改为 `22022.45` 万元后，预期合计 `31155.57` 万元、差额 `100` 万元，并明确它是方案假设；原文行及旧运行不变。

失败条件：识别把子项和顶层项混加、将比例当金额、缺一项却以零填补、差额 0 被显示为缺值、公式或单位错误仍提交、来源丢失、把“分项算术一致”写成“资金已落实/投资合理/独立审定”，或方案假设覆盖原文事实。此案例只验证选定五行的算术与软件追溯，不证明投资专业口径或原报告真实性。

### UX-29E 实测结果

独立测试库中新建项目上传固定公开 PDF，页面识别第 177 页 12 个表格行，从中逐一核对五条顶层金额。每条候选的名称、金额、单位与原文 ref 均通过页面核对后进入事实台账；七条子项没有被自动并入计算。两条明确创建的规则把四项算出 **31255.57 万元**，与原文总投资的差额为有效 **0 万元**。章节映射、方案预览、运行结果、候选、Plate 刷新及导出均显示相同数值。DOCX/PDF 解包与审计确认五个上游输入各自的原件 SHA、解析修订、证据 ID 和第 177 页表 1 对应行；页面只称“按本项目事实计算”，没有宣称资金落实或独立审定。PDF 一页已渲染目视检查，中文标题、表格、规则与来源位置可读。

复制方案只把工程费输入改为 **22022.45 万元**。首次预览显示合计 **31155.57 万元**、差额 **100 万元**，点击取消后没有保存运行，方案原输入仍为 22122.45。再次预览并保存后，界面比较展示两套结果；新运行将改动项标为 `scenario_assumption`，项目事实仍为 22122.45，旧运行仍为 31255.57。选择新运行后旧正文引用保持原样并转为待更新，情景分析导出返回 409；新候选准确使用方案措辞，取消候选不覆盖旧正文。关闭侧栏后会回到当前章节，避免焦点跳至报告开头。

首次断言暴露事实台账 `0.00` 与不可变运行规范化 `0` 的文本差别，两者都代表有效零，验收改为分别检查实际快照而非强求同一字符串。另一次实测发现复算段落仍写“本方案采用”，以及切换运行后关闭侧栏使当前章失焦；均已修复后重新跑通。真实前后端 `table-writing.spec.ts` **3/3** 通过；后端章节、运行、导出和表格目标测试 **40/40** 通过。此测试的规则目标和表达式通过项目接口建立，候选审核、章节配置、推演、对比、正文及导出通过浏览器操作；规则创建页面另有既有流程验收。本轮无迁移，没有写入日常数据库。

仍需用户判断哪几行属于同一口径、原文总额是否可信、是否遗漏跨页/表外费用；本案例没有自动发现总分项关系，也没有独立核实投资专业合理性。五行计算不能替代整份可研审核。
