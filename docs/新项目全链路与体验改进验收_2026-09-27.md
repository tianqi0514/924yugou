# 新项目全链路与体验改进验收（2026-09-27）

## 固定案例

原件为已保存的公开文件 `test-fixtures/public-reports/01_beijing_feasibility.pdf`，在独立 `report_platform_test` 数据库中创建新项目。人工核对位置为 PDF 实体第 7 页 `p7-s3`：地上建筑面积 15,756.25 ㎡、地下建筑面积 1,512 ㎡、总建筑面积 17,268.25 ㎡。第 8 页 `p8-s5` 含总投资 31,255.57 万元。验收不将这些历史报告值称为新建设项目的已核实事实；它们只是这份公开报告的来源陈述。

| 步骤 | 预期 | 失败条件 |
| --- | --- | --- |
| 新建与上传 | 新项目为空，上传后可定位第 7、8 页及原文片段 | 继承澄岳数值或无法定位长文档片段 |
| 事实与来源 | 三项面积事实逐项录入并绑定第 7 页同一原文片段 | 值、单位、来源或证据绑定丢失 |
| 推演 | `15756.25 + 1512 = 17268.25` ㎡；原文总量减计算量为有效 0 | 0 被视为缺失、单位错误或结果无公式来源 |
| 变化 | 地上面积在方案副本改为 15,000 ㎡，计算合计变为 16,512 ㎡，与原文总量相差 756.25 ㎡ | 原事实被改写，或旧运行跟着变化 |
| 写作与导出 | 两章候选确认后 Plate 保存、刷新、核对、导出；DOCX/PDF 和审计均包含本次运行的数值 | 仅 HTTP 成功但内容不一致、取消候选后入稿 |

## 本轮功能清单

每一项对应真实用户操作；“受控浏览器”使用接口替身，“真实链路”使用独立 PostgreSQL 与实际前后端。对取消、来源和导出另外核对服务端状态。

| ID | 用户动作 / 成功条件 | 验证 |
| --- | --- | --- |

## 实际项目与结果

本机应用保留项目“验收 · 北京交通枢纽面积与投资 2026-09-27”（项目数据库记录不随 Git 发布），包含公开原件、4 项逐一绑定的项目事实、一个已发布两章配置、两次不可变运行和两份两章情景分析报告。原文复算报告的面积合计 17,268.25 ㎡、差额 0；面积调整报告只改变方案输入中的地上面积为 15,000 ㎡，得到合计 16,512 ㎡、差额 756.25 ㎡。原项目事实仍为 15,756.25 ㎡，第二份报告显示“方案假设”。两份报告的最新版本均已核对、情景分析导出成功；正式事实稿因假设受到阻断。旧导出文件保留，新版本只去掉与审核状态矛盾的固定流程句。

独立测试库的真实浏览器路径还做了候选取消无入稿、Plate 人工补充、保存刷新、选第二运行、局部数字和条件更新、歧义值人工编辑后重绑、再次核对、两版导出及旧交付字节不变。解包检查 DOCX 各有 2 张表，解析 PDF 及审计中的报告版本、运行 ID、数值与正文；可见项目最新两版导出均为报告 v4、PDF 各 1 页。接口替身测试只证明相应交互，不作为真实抽取或专业成稿证据。

本轮最终回归：独立测试库后端 **134/134 通过**；前端受控浏览器 **15/15 通过**；真实前后端集成 **8/8 通过**；新增定位断言的北京链路单项再通过，`npm run build` 通过。过程中两条旧浏览器测试依赖旧的新项目默认页，已改为显式进入事实台账；一次推演变化检查的测试在请求尚未返回时计数，已等待操作列表出现。这些是测试时序与导航假设，未把它们误记为产品缺陷。产品层面修正了方案假设与事实事后变化的分类、列表核对状态、搜索迟到响应、抽屉 Esc 和已核对报告中的固定待核对句。生产构建仍提示主 JS 约 1.49 MB，后续需要按工作台与图谱拆包并做加载性能基准。

导出的 PDF 已渲染实看：中文、标题、两张表、数值、来源与页脚均可读，无截断或重叠。人类可读的“事实依据”目前只列正文直接绑定的事实；推演上游输入可从工作台公式和审计快照追溯，仍需把完整计算依据更清楚地排进交付文档。

尚未验证：205 页原件的全部章节是否能支撑专业成稿，大量项目和原件的全文搜索性能，以及非配置章节的模型质量。本轮使用确定性章节候选，没有将其称为真实模型起草；北京样本仅限面积和投资核对两章，不能据此宣称通用自动写作已完成。
