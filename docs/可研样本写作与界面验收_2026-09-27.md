# 可研样本写作与界面验收（2026-09-27）

## 固定案例与失败条件

使用仓库内 205 页的 `test-fixtures/public-reports/01_beijing_feasibility.pdf`，只核对建筑面积与投资摘录两章。原件第 7 页的地上面积 15,756.25 ㎡、地下面积 1,512 ㎡、总面积 17,268.25 ㎡及第 8 页的总投资 31,255.57 万元是来源陈述，不升级为新建设项目的独立事实结论。

| 案例 | 预期 | 失败条件 |
| --- | --- | --- |
| 原文复算 | 分项面积 17,268.25 ㎡，差额为有效 0；候选可单项选择 | 0 被当作缺失；结果表只有扁平原始文本 |
| 方案变化 | 地上面积改为 15,000 ㎡，分项面积 16,512 ㎡，差额 756.25 ㎡ | 原项目事实被改写，旧运行或无关人工正文被覆盖 |
| 模型起草 | 输入仅为本章运行值、批准条件和已核对证据；候选须绑定结果 | 来源外数字、错误条件或无引用段落进入报告 |
| 取消 | 模型或确定性候选取消后，报告版本与正文不变 | 预览造成持久修改 |
| 交付 | DOCX、PDF 与审计包含本次运行数值；人类可读附件列上游输入、公式和代入值 | 文件只存在但内容不符；PDF 出现仅一行的孤页 |

## 本轮实现与实测

1. 北京已保存报告的真实文本模型预览返回一个绑定 `reported_total_area`、`calculated_total_area`、`area_difference` 的候选段落，条件句原样保留，证据状态为 3/3 已核对。浏览器点击“取消候选”后，报告仍为 v4，正文逐块相同。另一轮模型请求曾返回缺少可核对结果引用而被原校验拒绝；新增的一次受控重试由测试替身覆盖“首次不合格、第二次合格”和“两次来源外数字均拒绝”，真实内网请求在改动后第一次即合格。因此不能把真实模型的重试分支称为已实测触发。
2. 生成面板显示当前方案与运行修订；本章数据、每块候选的结果和证据按需展开。结果表以表格呈现，可勾选段落或表格。桌面 1440 px 时面板宽 330 px，正文纸张宽约 820 px，页面未出现整体横向滚动；1100 px 与 850 px 时面板成为抽屉。850 px 下候选表宽 376 px、两列各约 188 px，数值均可见。模型段落与计算内容分开标识。
3. 导出只收集正文已引用结果及其上游。第二运行的 DOCX/PDF 均含“地上建筑面积 15000㎡（方案假设）”“分项计算建筑面积 16512㎡”和“原文与分项差额 756.25㎡”，规则和代入值使用业务字段名；完整运行快照仍在 `audit.json`。未经引用的指标不进入人类可读依据页。
4. 首次渲染新增依据后，北京固定两章 PDF 有 2 页，第二页只有一行事实来源。调整附录字号、行距和段距后重新渲染为 1 页；已人工目视检查中文、两张结果表、推演依据、事实来源及页脚，未见截断或重叠。DOCX 解包、PDF 文本解析和审计结果数值均通过校验。
5. 旧报告曾按审计水位复用已保存 ZIP，因此同一报告版本再点击导出可能得到旧排版。导出审计现增加 `render_version` 并纳入水位；格式升级后同一报告版本可生成新版 ZIP，原交付 ID、字节与重下载入口均保留。独立测试库的旧版→新版格式切换、重复请求复用、旧文件重下载和后续正文版本变更均通过。

## 范围与待做

本轮只证明北京可研样本的面积核对和投资摘录两章可走通；模型输出需人工专业核对，尚无第三方审定的可研写作金标。没有把澄岳历史 30 类复制到北京项目，也没有证明 30 类对北京报告都必要。长文档全部章节、建设项目专业判断、跨项目资料适配和真实模型连续失败后的用户恢复仍需验证。模型预览、界面样式和导出格式的改动未迁移数据库；测试写入只在 `report_platform_test`，现有本机报告只做只读预览与取消。
