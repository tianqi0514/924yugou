## 实际结果

真实前后端自动化使用独立 `report_platform_test`，由全局准备脚本先断言数据库名再运行；本机日常库只创建了专用 QA 项目，没有重建表或改动其他项目。专用项目 `c30b1f0b-62bc-468f-a01a-c83b6a96780a`，报告 `42c4b373-d14e-4ef3-9669-49adcef11ce0`，可从项目切换器打开。原件事实 `total_investment` 与 `environmental_investment` 分别入台账并绑定同一 PDF 物理页 5 片段 `p5-s8`；位置已由操作者核对，不能据此宣称公开报告中的事实经过独立鉴证。

| 检查 | 真实结果 |
| --- | --- |
| 候选取消与两章入稿 | “投资基本情况”候选取消后报告无该章节；重新生成后加入。“环保投入情景”基于同一份运行加入，Plate 刷新保留两章、两张表和运行引用。 |
| 推演与条件 | 20 万元预算上限时，预算内剩余空间为 3 万元，条件句为“未超过”；15 万元上限时为有效 0，条件句变为“超过”。预算上限是情景假设，不是原件事实或监管标准。 |
| 真实模型 | 本机已配置的文本模型对第二章的两个运行各实际调用一次；输出均通过受限数字、禁用语和条件句校验并被采用。两次采用事件与调用摘要进入审计，不含密钥。第一章只使用确定性候选。 |
| 数据变化 | 选择新运行后旧正文阻断核对；重新生成第二章后发现第一章虽然数值不变，引用仍指向旧运行。通过“处理变化”更新第一章的段落与表格绑定，正文未被重写，之后重新核对通过。旧报告版本和旧导出仍指向原运行。 |
| 导出质量 | 本机 `deliverables/eia-validation/` 中两份 ZIP 均含 DOCX、PDF、audit.json；解包验证两张表、两章关键数值、条件句、项目/报告/运行/版本和证据位置。两份 PDF 各 1 页，渲染目视检查中文、表格、页边距与来源尾注，无截断或溢出。旧稿不含新条件，新稿不含旧条件或旧差额。 |
| 页面与回归 | 本机 5173/8000 页面实测统一五项菜单、项目资料空状态、打开报告→资料/文件→返回同一报告、刷新、500 px 窄屏无横向溢出、无页面脚本异常。未保存正文切菜单会被拦住，自动保存完成后可切换。独立前后端集成 5/5；受控前端 13/13；`eia-writing.spec.ts` 覆盖取消、入稿、变化、局部更新、核对、情景分析导出与未保存导航拦截。 |

本轮没有消费澄岳 30 类中的任何记录；公开环评仅被建为独立项目原件，其数据由操作者选取两项建立事实与证据。报告只验证两个显式配置章节的情景分析，没有验证污染物计算、排放限值、法规适用、审批结论或环评报告全篇质量。正文的专业语义仍需环评人员核对；本次模型句子只约束在“投资额与自定预算”的范围。
