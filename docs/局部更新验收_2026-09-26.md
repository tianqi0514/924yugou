本文件在实现前固定案例。测试使用 `report_platform_test`，真实浏览器验证另记；澄岳历史数据只作情景假设。

| 案例 | 输入与操作 | 预期 | 失败条件 |
|---|---|---|---|
| L1 产能变化 | 需求 300000；工作日 300→250；选新运行 | 段落中能力/销售 254016→211680，结果表同值更新，条件仍为产能受限；只选段落更新时表格继续待更新 | 漏掉表格引用、覆盖其他章节或人工文字、把未选动作视为已处理 |
| L2 条件变化 | 基准需求 300000→200000，能力 254016 | 销售 200000；数字、表格和“需求低于能力”作为独立动作；只改数字和表格仍阻断核对 | 留下“需求超过能力”却允许情景分析导出 |
| L3 身份变化 | 供应商改为“新供应商甲”，报价缺失 | 仅对受审引导段落给出新供应商判断候选；不带入禾进装备、旧报价或采购建议 | 无报价当成 0，或覆盖用户人工改写 |
| L4 保护与失败 | 预览后取消、并发版本、重复确认、缺值或跨项目运行 | 预览不落库；确认原子保存报告新版本和操作记录；失败无半提交；人工块保留并明确待处理 | 旧引用被静默升级，历史版本或无关段落改变 |
| L5 页面与导出 | Plate 保存刷新后处理影响、核对与导出 | 每处可见旧文/新文，能选择动作并返回原报告；DOCX/PDF/审计绑定同一运行与报告版本 | 页面只显示技术 ID、操作后跳出工作台、导出文件与审计水位不一致 |

## 实际验证

| 范围 | 结果 |
|---|---|
| L1 数字与表格 | 后端测试按固定的 300→250 天输入验证 254016→211680；预览无写入，只提交段落后表格继续阻断，第二次提交后可重新核对与导出。真实浏览器在独立 QA 报告做反向 250→300 天验证：v3 绑定新运行，v4 只更新正文，v5 才更新表格；剩余阻断由 12 条逐引用提示降至 1 条未核对提示。 |
| L2 条件 | 后端按需求 300000→200000 验证销售量 200000；只更新数字和表格时仍有 `ANALYSIS_CONDITION_STALE`，核对失败；单独更新条件句后旧判断消失。 |
| L3 供应商 | 后端将历史供应商改为“新供应商甲”，候选没有“禾进装备”和旧报价；后续人工改写段落被识别为只供核对，不能自动覆盖。 |
| L4 保护和版本 | 预览不改变正文；同一旧版本重复提交返回 409；历史报告版本可读取；人工改动保留，旧引用继续阻断。缺值运行不能被选作报告主运行。 |
| L5 页面与导出 | 在运行中的 5173/8000 工作台新建 `QA · 局部更新界面验收 2026-09-26`，逐项打开预览、选中、确认、刷新、核对、点击情景分析导出；页面保持当前报告。导出 ZIP 内含 DOCX、PDF、audit.json；解析 DOCX 与 PDF 均有 300000、254016、45984，审计含运行 `a2f0d5c5-7aad-4528-8803-02c527fddf07`，PDF 为 1 页。900px 宽浏览器截图检查右侧面板可关闭，正文未横向溢出。 |

界面核查另发现 Plate 表格包含嵌套块，按 DOM 顺序索引定位会误跳到表格单元格；章节、阻断项和局部更新的位置按钮已改用稳定块 ID 定位。浏览器错误日志为空。

独立 `report_platform_test` 数据库全量后端回归 **121/121 通过**；本功能文件定向 **12/12 通过**；前端受控 API 浏览器回归 **13/13 通过**，TypeScript/Vite 构建通过。真实浏览器操作使用日常本机库中的独立 QA 报告，未改写原有的“澄岳精密项目专题整理”。

## 边界

- 自动更新仅用于受审引导块、已绑定的数字/结果表、S4 已知需求条件句及 S7.1 供应商判断。人工句内改写、人工表格和其他自由正文只定位并要求人工核对。
- 当前的“处理变化”是即时接口调用，不是服务重启后可恢复的后台任务。旧导出文件重取与规则独立发布仍在开发清单中。
- 此次验证证明澄岳限定情景分析流程中的局部更新可靠，不证明任意行业报告的语义差异可以自动处理。
