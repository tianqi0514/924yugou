# 交付与编辑恢复验收（2026-09-26）

## 实施前固定案例

| ID | 输入与操作 | 预期结果与失败条件 |
|---|---|---|
| D1 | 已核对报告导出情景分析包，重复请求同一报告版本与审核水位 | 历史交付列表只新增一条，同一交付 ID、ZIP 字节与 SHA256；文件内审计列出交付身份、版本、运行和交付级别 |
| D2 | 导出后修改正文或选择新运行，再下载旧交付 | 旧 ZIP 字节、正文、数值和审计不变；新报告版本产生新交付；跨项目下载和不存在的 ID 返回错误 |
| D3 | 缺证据、未核对或不可评估时报错导出 | 不产生成功交付记录或可下载的空文件；界面显示简短错误并可重试 |
| D4 | Plate 正文变更后模拟保存失败、刷新、选择恢复 | 待保存内容只保存在当前浏览器会话；恢复后仍标待保存，确认保存产生正常报告版本；选择放弃时服务端内容不变 |
| D5 | 待恢复正文基于旧报告版本，服务端已有更新 | 明确提示版本变化；不会自动覆盖服务器；用户可复制待恢复内容或放弃，旧版本原样保留 |
| D6 | 打开输入/结果/检查侧栏，编辑器已有光标，关闭侧栏或按 Esc | 焦点与选择回到 Plate；章节与正文滚动上下文保留；未保存内容不被重置 |

## 数据保护

持久化变更前备份位于本机 `backups/delivery-recovery-20260926/`：`report_platform.dump` 和 `documents.tar.gz`，不提交 Git。所有会写测试数据或重建表的测试只在 `report_platform_test` 上运行并断言库名。恢复演练仅在隔离库进行，不覆盖日常项目。

### 隔离恢复演练

使用 PostgreSQL 16 将迁移前 dump 导入新建的 `report_platform_restore_check_20260926`，将原件归档解压到独立 `tmp/` 目录；备份包含 14 个原件文件。隔离后端以 8002 端口启动成功，健康检查正常，读取 20 个项目、18 份报告、13 条原件记录及澄岳语料 `v2`；启动时非破坏创建新增交付表。完成后关闭隔离后端、删除隔离数据库和临时解压目录，日常库未被恢复操作覆盖。此演练验证该备份可恢复到应用可读状态，未验证跨机器恢复或所有上传文件逐一打开。

### 当前边界

恢复副本只覆盖当前浏览器会话，不支持跨设备、关闭会话后的同步或自动合并冲突段落。历史 ZIP 存在 PostgreSQL 中，适合当前本机报告大小；尚未做大文件配额、异步任务、长期归档与自动清理。保存的旧交付只能按原字节重新下载，不能视为当前项目的新审核许可。
