## 2. 实际浏览器闭环

澄岳内置项目 → 显式复制历史输入 → 首年需求改为 300000 → 预览并取消 → 再预览保存基准运行 → 用真实内网文本模型生成 S4 候选、取消、再次生成并确认 → 复制方案，工作日改为 250、供应商改为新供应商甲 → 保存第二运行并与基准对比 → 选择第二运行，旧引用出现阻断 → 只替换 S4 → 新增 S7.1 和 S5.2 → 人工核对 → 情景分析导出。历史文章原有版本仍在版本表中。Plate `/` 菜单已在浏览器弹出；一次测试输入影响表格后通过正式预览/保存接口恢复 v7 正文为 v9，随后补上 L002/EV-01 回链形成 v10 并重新核对，未把测试字符留在交付文件中。

普通项目另测：新建 `QA · 空白方案工作台 2026-09-26`，新建报告和“从项目事实创建”的空白方案，界面提示先录入项目事实；无澄岳历史值。此项目是实际本机 QA 记录，不是业务证据。

真实模型调用的第一次尝试被数字闸门拒绝，后续修复为只传本章限制、允许由运行支持的差额、避免把否定的“并非已签订单”误判为正面声明；之后候选成功。最终导出的 S4 为确定性内容，`audit.json` 的当前版本模型使用记录为 0；旧版 v3 的模型候选与事件仍保留，不能说最终版由模型撰写。
