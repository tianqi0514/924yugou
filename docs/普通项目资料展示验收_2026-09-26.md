# 普通项目资料展示验收（2026-09-26）

## 问题与修正

原“项目资料”页面仅按 `has_corpus` 判断是否展示澄岳 30 类语料。普通项目即使已上传文件并审核事实，也直接显示“暂无项目资料”。这把“历史语料”错误地当成“项目资料”的全部内容。

现在两类项目使用同一个菜单名称、不同的真实数据来源：澄岳继续只读浏览已入库的 30 类历史语料；普通项目汇总自己的原件、解析段落数量和事实台账。事实详情调用现有来源接口，区分已核对原文、规则推导和待核对来源。文件可定位到“项目文件”具体条目，URL 带文件 ID，刷新后仍选中该文件。空项目只在确无记录时显示空状态。此修正没有复制澄岳历史值，也没有为普通项目伪造 30 类产物。

## 固定验收案例与结果

| 案例 | 预期 | 实际结果 |
|---|---|---|
| 空项目 | 原件、段落、事实均为 0；上传与事实入口可用 | 受控前端浏览器验证通过 |
| 江门环评项目 | 已有 PDF、解析文本和事实时不显示“暂无项目资料” | 日常库只读核对：1 份 65 页原件、686 段、2 条事实；实际页面显示一致 |
| 事实来源 | 总投资 500 万元可回到第 5 页已核对的 `p5-s8`；未知来源不得标已核对 | 独立测试库真实前后端浏览器验证通过 |
| 文件定位 | 从资料页进入相应文件，刷新仍选中；项目导航返回报告 | 独立测试库真实前后端浏览器验证通过 |
| 屏幕宽度 | 资料页在 500px 宽度下无整体横向溢出 | 独立测试库真实浏览器验证通过 |

本轮只复用了既有只读接口与前端路由，没有数据库迁移或对日常项目写入。文件的待审抽取候选仍在“项目文件”中按页核对；普通项目尚不能自动生成澄岳式 30 类结构。

验证命令：`npm run test:integration -- --grep '环评样本两章|数据库内 30 类'`，真实前后端 `2 passed`；`npm run test:e2e`，受控前端 `13 passed`。日常库只读浏览器检查与 500px 窄屏检查通过；构建通过。
