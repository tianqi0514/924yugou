# 规则计算操作验收 · 2026-09-27

## 范围与现状

本轮改进项目事实之后的规则创建和结果核对。当前服务端已有 Decimal、受限表达式、循环与单位检查，但界面直接提交规则，列表长期展示原始表达式，用户难以在保存前判断结果及影响。现有 `POST /rules` 为兼容接口；新界面改用预览和确认流程。历史项目继续只读。

## 固定验收案例

| 输入或操作 | 预期 | 失败条件 |
| --- | --- | --- |
| 需求 300000 套、能力 254016 套，目标销售，`min(demand, capacity)` | 预览 254016 套，预览时规则和项目版本不变；确认后刷新仍在，详情可看两个代入值 | 预览写库、结果错误、依据不可查 |
| 需求改为有效 0 | 结果为 0 套，状态为已计算 | 0 显示缺失或沿用 254016 |
| 需求清空 | 结果不可评估，指出缺少需求 | 用 0 或旧值替代 |
| 需求和能力单位不一致 | 预览明确报错，规则未创建 | 半提交或提示“成功” |
| 循环依赖或除零 | 预览明确报错，规则未创建 | 产生无效规则 |
| 预览后取消 | 无规则及目标变更 | 取消仍有修订 |
| 预览后项目事实变化再确认 | 409，要求重新预览 | 使用过期结果提交 |
| 结果事实已有规则 | 不可重复写入同一目标 | 两条规则竞争目标 |

## 实施顺序

1. 后端增加只读规则预览与带凭证确认，复用原计算器与项目版本锁。
2. 前端只显示规则名称、结果和状态；创建时可从项目事实插入字段，预览后确认；点规则查看输入、表达式与结果。
3. 先测后端零写入及错误，再测前端按钮、取消、刷新和窄屏，最后跑相关既有写作闭环。
