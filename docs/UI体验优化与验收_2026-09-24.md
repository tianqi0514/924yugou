# UI 体验优化与验收（2026-09-24）

## 本轮调整

- 左侧只保留当前项目可用的主入口：项目文件、项目事实、规则计算、报告写作。历史项目进入项目资料；案例验证和模型配置放在次级区域。
- 事实台账只在列表显示事实、值、状态和操作。来源、修订和其他属性在操作时展开；新增事实可选择直接录值或仅创建定义。
- 项目文件优先显示原文和待审候选，已处理记录与技术细节按需展开。
- 报告写作按章节起草、Plate 编辑、核对导出排列。写作包的事实槽位可在报告页直接映射到本项目事实；候选必须确认后入稿。
- 内置 30 类资料按七组、类别、业务记录、文件逐层进入；类别预览优先于原始文件列表。图谱选中节点时保持画布可见，详情由按钮打开。
- 精简固定的页面说明和空态文案；保留错误、证据限制、冲突和导出闸门的具体原因。
- 当前项目入口和所选报告会在刷新后恢复。Plate 段落拆分时，只有内容原样移到新段落才转移原段落 ID 与已确认来源；空段落不继承事实或来源。保存预览按内容对齐，插入表格不再把后续正文误报为重写。

## 隔离浏览器实测

测试使用 `report_platform_test`，后端监听 `127.0.0.1:8001`、前端监听 `127.0.0.1:5175`；两者在验证后关闭。用户原有 `8000/5173` 服务和应用数据库未用于写测试数据。测试原件为 `test-fixtures/ux-integration/项目事实_QA合成原件.docx`，其中只有三项合成数值。

1. 新建空白项目，上传 DOCX，原文按段可查看；录入需求 300,000 套和合格能力 254,016 套，建立 `min(first_year_demand, qualified_capacity)` 规则，得到计划销售量 254,016 套。为两个输入绑定原文件片段。
2. 创建空白报告，选择澄岳 v2 的 S4，直接在报告页把 N017、N034、N035 映射到本项目事实。写作包显示三个当前值。核对五项必选记录后预览候选；取消后报告仍为 v0。重新预览并确认后，报告变为 v1，正文包含 300,000、254,016 和“需求不是订单”的限定表达，没有继承历史“需求低于能力”句子。
3. 在 Plate 输入 `/` 打开命令菜单，插入 2×2 表格，并在单元格插入本项目事实 token。保存后刷新，表格、数字、历史来源和规则仍在；源段落 ID 保持不变，正式导出只剩“未人工核对”一项阻断。点击“我已核对”后正式导出可用。
4. 实际解包正式 ZIP：`report.docx`、`report.pdf`、`audit.json` 均存在。DOCX 有一张表，正文含 300,000、254,016；PDF 同样含数字、表格与需求限定句；审计 JSON 含三个事实 key。500 px 视口的报告页无横向溢出，顶部导航、Plate 工具栏和表格可用。
5. 把需求预览为有效值 0，预览显示计划销售量变为 0、11 处既有报告引用受影响；取消后仍为 300,000。再次预览并确认后，台账显示需求 0、项目版本增加，报告显示过时引用并阻断正式导出。新修订没有对应的原文件证据，阻断属于预期行为。

历史语料浏览器在本轮逐类打开 30/30 类，均有非空主视图；浏览器可定位 117 个入库文件，复杂关系保留列表和局部图谱。此项检查仅验证可浏览性，不等于 30 类都对成稿有增益。
