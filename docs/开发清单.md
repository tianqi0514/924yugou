# 开发清单与验收基线

版本：2026-09-24。本文是后续开发的统一清单；产品范围见[PRD](产品需求文档.md)，实现约束见[详细设计](详细设计文档.md)。本轮先整理现状与交付代码，不把下列未完成项当作已经开发。

## 状态与使用方式

- **已实现**：代码路径存在且有对应测试或操作记录；仅覆盖所列范围。
- **部分实现**：有可用路径，仍有明确缺口。
- **待开发**：尚未形成可用实现。
- **待验证**：有假设或实现，但没有足够实验支持。

每次开发先选清单 ID，固定输入、预期与失败条件；完成对应代码、测试与用户操作验证后再更新状态和证据。未运行的测试写“未运行”。界面只展示当前可用的操作、必要状态与问题，不添加宣传说明或无功能按钮。新增 Plate 节点须同时完成前端、后端校验、数据库往返、版本比较、事实绑定及导出。

优先级：P0 为当前闭环的正确性与交付基础；P1 为扩展有效写作覆盖；P2 为经需求验证后再实施。多用户上线前须完成安全与迁移项，不能因排为 P1 而直接跳过。

## 每项任务交付检查

- [ ] 绑定一个或多个清单 ID，说明用户能完成的动作。
- [ ] 开发前冻结输入、期望、失败条件，写清前置依赖。
- [ ] 测试只连接并断言 `report_platform_test`，不与其他重建测试并行。
- [ ] 浏览器验证按钮、错误/空值状态、刷新与窄屏；不是只做构建检查。
- [ ] 涉及成稿时核查正文、来源、规则、保留事项及导出文件。
- [ ] 更新 PRD、详细设计、此清单与验收记录；保留失败和未测内容。
- [ ] 提交前排除模型密钥、个人原件、运行数据和数据库备份。
